# 23. Default Pricing and Price Onboarding

## 1. Purpose

Pricing must be useful, but users must understand that default prices are examples and should be adjusted to their own rental/mounting/delivery rates.

## 2. v1.0 pricing principle

Default pricing may exist, but must not pretend to be universal market pricing.

Recommended copy:

```text
Цены примерные. Настройте свои ставки в разделе «Настройки цен».
```

## 3. Default pricing behavior

Recommended:

- show price settings early;
- allow editing price profiles;
- store prices locally;
- include price profile name/version in saved calculation;
- include price warning if values are defaults.

## 4. First launch pricing hint

When pricing is shown for the first time:

```text
Проверьте ставки аренды, монтажа и доставки перед отправкой PDF.
```

## 5. PDF pricing note

If defaults are used, PDF may include subtle note:

```text
Стоимость рассчитана по текущему профилю цен. Проверьте ставки перед отправкой клиенту.
```

## 6. Per-calculator price areas

Stage:

- price per module;
- mounting;
- delivery;
- stairs/closure if priced.

Truss:

- rental per meter or per part depending catalog rules;
- nodes/angles/base pricing;
- mounting;
- delivery.

LED:

- price per cabinet/module/day;
- mounting;
- delivery;
- accessories if priced.

## 7. Acceptance

Accepted when user can clearly see and edit pricing assumptions and no PDF hides the fact that pricing depends on configured rates.
