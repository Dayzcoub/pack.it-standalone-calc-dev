# 00. PDF Legal and Metadata Policy

## 1. Purpose

PDF files may be sent to clients, colleagues or technicians. They must be clear, traceable and legally cautious.

## 2. PDF is not

A PACK.IT PDF is not:

- a contract;
- an invoice;
- an engineering certificate;
- a structural approval;
- a safety guarantee;
- a manufacturer document.

## 3. Required PDF metadata/content

Every PDF should include where practical:

- generated date/time;
- appVersion;
- calculationEngineVersion;
- catalogVersion;
- pdfTemplateVersion;
- price profile name/version if pricing is shown;
- calculator type;
- input summary;
- result summary;
- warnings;
- disclaimer;
- PACK.IT brand.

## 4. Disclaimer

Short PDF disclaimer:

```text
Справочный расчёт. Перед монтажом проверьте по паспортам оборудования, требованиям производителя и нормам безопасности.
```

Extended note if needed:

```text
PDF не является договором, счётом или инженерным заключением. Расчёт выполнен по введённым данным и текущим настройкам приложения.
```

## 5. Pricing note

If pricing is shown:

```text
Стоимость рассчитана по выбранному профилю цен. Проверьте ставки перед отправкой клиенту.
```

## 6. Catalog note

If built-in or user-defined catalogs are used:

```text
Комплектность рассчитана по выбранному справочному каталогу. Перед монтажом проверьте паспорт оборудования и совместимость элементов.
```

## 7. Old saved calculations

PDF generated from a saved calculation should use the saved resultSnapshot unless user explicitly creates a recalculated copy.

## 8. Acceptance

Accepted when PDFs are traceable, include disclaimers and cannot be mistaken for certified engineering documentation.
